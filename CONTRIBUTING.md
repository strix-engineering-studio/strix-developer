# Contributing

1. Use Markdown or MDX under `src/content/docs/`.
2. Use Starlight frontmatter with a clear title and description.
3. Keep one topic per page and group product documentation under `products/`.
4. Include prerequisites, tested versions, exact commands, expected results, and recovery notes.
5. Never commit secrets, credentials, or confidential customer data.
6. Run `npm install`, `npm run check`, and `npm run build` before opening a pull request.
